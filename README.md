# เว็บแชตความจำ 4 ชั้น

เว็บที่รันในเครื่อง ใช้ทดลองระบบความจำ 4 ชั้นตาม `DESIGN-AND-TESTS.md` ผ่าน OpenRouter
ข้อมูลทั้งหมดเก็บใน `data/memory.db` (SQLite) ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ใช้แค่ Python 3.10 ขึ้นไป

## เริ่มใช้

```bash
python server.py
```

เบราว์เซอร์จะเปิด `http://127.0.0.1:8765` ให้เอง จากนั้น:

1. ใส่ OpenRouter API key
2. เลือกโมเดล 3 ตัว ช่องโมเดลมีรายชื่อจาก OpenRouter และบอกราคากับขนาด context
   - **ตัวสรุป:** สรุปเทิร์นเก่าเป็นราย ID
   - **ตัววิ่งหาข้อมูล:** อ่านสรุปทุก ID แล้วเลือก ควรเป็นโมเดลราคาถูก
   - **ตัวทำงานหลัก:** คุยกับผู้ใช้ **ต้องรองรับ tool calling** ถ้าไม่รองรับ หน้าตั้งค่าจะเตือน
3. สร้างแชตใหม่แล้วเริ่มคุย

ตัวเลือกอื่น: `--port 9000`, `--db path/to/other.db`, `--no-browser`

## สิ่งที่ระบบทำในแต่ละข้อความ

1. ปิดรายการในชั้น 4 ที่หมดอายุ
2. ถ้าติ๊ก "บังคับสแกน" หรือข้อความมีคำที่อ้างถึงเรื่องเก่า เช่น "ที่เคย" "ก่อนหน้า" "ที่ตกลง" ระบบจะสแกนก่อนตอบ (ข้อเสนอ 13.1)
3. ส่ง prompt ให้ตัวทำงานหลัก ประกอบด้วยกฎของระบบ ชั้น 1 และข้อความล่าสุดที่มี `<memory_state>` (ชั้น 4) ต่อท้าย
   ถ้าชั้น 4 ยาวเกิน `state_cap_chars` ระบบจะเอาสรุปหรือข้อความเต็มที่ดึงมาเก่าที่สุดในชั้น 4b ออกก่อน ไม่แตะชั้น 4a และโน้ต
   คำตอบส่งกลับมาที่หน้าเว็บแบบสตรีม (`POST /api/chats/{id}/send_stream` ส่ง JSON ทีละบรรทัด) ถ้าปิดหน้าเว็บกลางคัน คำตอบยังถูกบันทึกครบ
4. ตัวทำงานหลักดูแลชั้น 4 เองโดยไม่ต้องให้ผู้ใช้กำหนด ชั้น 4 แบ่งเป็นสองส่วน:
   - **4a (ปักไว้ทั้งแชต ไม่หมดอายุ):** `condition` คือคำของผู้ใช้ตรงตัว และ `decision` คือสิ่งที่ผู้ใช้ตกลงแล้ว
   - **4b (ความจำระหว่างทำงาน หมดอายุเอง):** `note`, `summary`, `full`

   tool ที่ตัวทำงานหลักเรียกได้:
   - `search_memory`: สแกนสรุปทุก ID ชุดละ `shard_size` ID รันพร้อมกัน ทุกชุดรายงาน `found`, `not_found` หรือ `failed` และชุดที่ล้มเหลวจะลองใหม่ 1 ครั้ง
   - `read_full`: อ่านข้อความเต็ม (ชั้น 3) แทนสรุปของ ID นั้นในชั้น 4
   - `pin_condition`: ปักเงื่อนไขในชั้น 4a เมื่อผู้ใช้บอกเป้าหมาย ข้อห้าม หรือรูปแบบที่ต้องใช้ตลอด ข้อความต้องคัดจากคำผู้ใช้ตรงตัว และแทนข้อเก่าได้
   - `record_decision`: บันทึกข้อตัดสินใจที่ผู้ใช้ตกลง และแทนข้อเก่าได้
   - `add_note`: ต้องอ้าง ID ที่ยังอยู่ในชั้น 1 ถ้าอ้าง ID อื่น โค้ดจะปฏิเสธ
   - `retire_state`: เอาของในชั้น 4b ออกได้ทุกเมื่อ ส่วนชั้น 4a เอาออกได้เฉพาะเมื่อผู้ใช้ขอในข้อความปัจจุบัน และต้องแนบคำของผู้ใช้ (`user_quote`)
5. หลังตอบ ถ้าชั้น 1 มีเทิร์นถึง `compress_at` (ค่าเริ่มต้น 25) จะสรุปรอบละ `round_size` ID อยู่เบื้องหลัง
   ตั้งค่าเริ่มบีบอัดกับขนาดรอบนี้ได้ทั้งแบบรวมในหน้าตั้งค่า และแบบแยกต่อแชตจากแถบบนของแชตนั้น (ไม่ตั้งไว้ = ใช้ค่ารวม)

## ระดับความคิด (reasoning effort) ของตัวทำงานหลัก

ตั้งค่าเริ่มต้นได้ในหน้าตั้งค่า และแยกต่อแชตได้จากช่องเลือกที่แถบพิมพ์ข้อความ (ไม่ตั้งไว้ = ใช้ค่าเริ่มต้น)
ระดับที่เลือกได้: ปล่อยตามค่าเริ่มต้นของโมเดล, none, minimal, low, medium, high, xhigh
ใช้ได้เฉพาะกับ **ตัวทำงานหลัก** เท่านั้น (ตัวสรุปกับตัววิ่งหาข้อมูลไม่ใช้ค่านี้) และมีผลเฉพาะโมเดลที่รองรับ reasoning เท่านั้น
(หน้าเลือกโมเดลจะบอกว่าโมเดลไหนรองรับ) ยิ่งตั้งสูง โมเดลจะคิดนานขึ้นและมีค่าใช้จ่ายมากขึ้น
ข้อความที่โมเดลคิด (reasoning) จะไหลออกมาในกล่อง "กำลังคิด…" ระหว่างตอบ แล้วพับเก็บไว้เหนือคำตอบให้เปิดดูย้อนหลังได้
ตอนโมเดลเรียก tool ระบบส่งความคิดก่อนหน้า (`reasoning_details`) กลับไปให้โมเดลด้วย เพื่อให้คิดต่อจากเดิมได้

## ชิ้นงาน (artifact)

เมื่อผลงานเป็นชิ้นใหญ่ที่ใช้ต่อได้ เช่น หน้าเว็บทั้งหน้า รูป SVG เอกสาร หรือโค้ดยาวเกินราว 30 บรรทัด ตัวทำงานหลักจะเก็บเป็นชิ้นงานแทนการพิมพ์ลงในคำตอบ

- tool: `create_artifact` (สร้าง v1), `update_artifact` (แก้ด้วย `edits` ที่ข้อความเดิมต้องเจอพอดี 1 ที่ หรือแทนทั้งชิ้นด้วย `content`) และ `read_artifact`
- แก้แต่ละครั้งได้เวอร์ชันใหม่ เวอร์ชันเก่ายังเก็บไว้ ประเภทที่รองรับ: `html`, `markdown`, `code`, `svg` ขนาดไม่เกิน 200,000 ตัวอักษรต่อชิ้น
- เนื้อหาชิ้นงานไม่อยู่ในข้อความแชต ชั้น 1 ตัวสรุป และบันทึก tool จะเห็นแค่ขนาด เช่น `<12,345 chars>` ส่วนชั้น 4 มีแค่รายชื่อชิ้นงาน โมเดลอ่านเนื้อหาเองด้วย `read_artifact`
- หน้าเว็บแสดงในแท็บ "ชิ้นงาน" ของแผงขวา (แผงขยายกว้างขึ้นตอนเปิดชิ้นงาน) มีตัวอย่าง ดูโค้ด เลือกเวอร์ชัน คัดลอก และดาวน์โหลด
- HTML แสดงใน iframe แบบ sandbox ที่ไม่มี `allow-same-origin` สคริปต์ในหน้าจึงอ่านข้อมูลหรือเรียก API ของแอปนี้ไม่ได้ SVG แสดงผ่าน `<img>` ซึ่งไม่รันสคริปต์
- API: `GET /api/chats/{id}/artifacts`, `GET /api/chats/{id}/artifacts/{aid}` (ล่าสุด) และ `GET /api/chats/{id}/artifacts/{aid}/versions/{v}`

## กฎที่บังคับด้วยโค้ด ไม่ได้พึ่งแค่ prompt

- `condition` ต้องเป็นส่วนหนึ่งของคำผู้ใช้ตรงตัว ทั้งที่โมเดลปักและที่ปักจากหน้าเว็บ (เทียบโดยไม่สนช่องว่าง) ข้อความที่แปลหรือเรียบเรียงใหม่จะถูกปฏิเสธ
- `note` ต้องอ้าง ID ในชั้น 1
- โมเดลเอาชั้น 4a ออกได้เฉพาะเมื่อ `user_quote` ตรงกับคำในข้อความปัจจุบันของผู้ใช้
- รายการซ้ำใน 4a จะไม่ถูกเพิ่มซ้ำ
- สรุปต้องได้ครบทุก ID ในรอบ ถ้าไม่ครบจะลองใหม่ 1 ครั้ง แล้วแจ้งข้อผิดพลาด โดยเทิร์นยังอยู่ในชั้น 1
- ตัวคัดกรองเลือกได้เฉพาะ ID ที่อยู่ในชุดของตัวเอง และสแกนเฉพาะ ID ที่สรุปแล้ว ไม่สแกน ID ที่ยังอยู่ในชั้น 1
- เพดานงบต่อข้อความ (`max_usd_per_message`) และจำนวนรอบ tool สูงสุด

## หน้าเว็บ

- **แชต:** คำตอบไหลออกมาทีละส่วนระหว่างที่โมเดลพิมพ์ และแสดงขั้นที่โมเดลทำ เช่น ค้นความจำ ปักเงื่อนไข แต่ละข้อความแสดง ID และบอกว่ายังอยู่ในชั้น 1 หรือสรุปแล้ว ปุ่ม 📌 (ชี้เมาส์ที่ข้อความ) ใช้ปักคำของคุณเป็นเงื่อนไขเอง
- **แถบบน:** จำนวนในชั้น 1 และชั้น 2 จำนวนรายการในชั้น 4a และ 4b ขนาดชั้น 4 เทียบเพดาน และค่าใช้จ่ายรวม ปุ่ม ⋯ มีคำสั่ง "สรุปรอบถัดไปตอนนี้" ส่งออก และลบแชต
- **แผงขวา:** พับเก็บหรือเปิดได้ด้วยปุ่มมุมขวาบน ระบบจำไว้ว่าเปิดหรือปิด บนจอแคบแผงจะเลื่อนออกมาทับแชต
- **แท็บชั้น 4:** แยก 4a กับ 4b ดู แก้ และเอารายการออกได้ ส่วนการเพิ่มเองซ่อนไว้ในหัวข้อ "เพิ่มเองด้วยมือ" เพราะปกติโมเดลจัดการให้
- **แท็บชั้น 2:** ดูและแก้สรุปราย ID
- **แท็บตรวจสอบ:** แยกตามข้อความ บอกขนาด prompt ผลสแกนทุกชุด tool ที่เรียก โทเคน และค่าใช้จ่ายของแต่ละการเรียก
- **แท็บทดสอบสแกน:** ลองถามตัววิ่งหาข้อมูลโดยไม่เปลี่ยนชั้น 4

## ความปลอดภัย

- เซิร์ฟเวอร์รับเฉพาะ `127.0.0.1` และปฏิเสธ Host ที่ไม่ใช่ localhost เพื่อกัน DNS rebinding
- คำขอที่เขียนข้อมูลต้องเป็น `application/json` เว็บอื่นจึงสั่งผ่านเบราว์เซอร์ของคุณไม่ได้
- API key เก็บใน `data/memory.db` แบบไม่เข้ารหัส และ API ไม่ส่ง key กลับมาให้หน้าเว็บ อย่าแชร์ไฟล์ db
