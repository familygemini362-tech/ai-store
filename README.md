# เว็บแชตความจำ 4 ชั้น

เว็บที่รันในเครื่อง ใช้ทดลองระบบความจำ 4 ชั้นตาม `DESIGN-AND-TESTS.md` ผ่าน OpenRouter
ข้อมูลทั้งหมดเก็บใน `data/memory.db` (SQLite) ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ใช้แค่ Python 3.10 ขึ้นไป

## เริ่มใช้

```bash
python server.py
```

เบราว์เซอร์จะเปิด `http://127.0.0.1:8765` ให้เอง จากนั้น:

1. ใส่ OpenRouter API key
2. เลือกโมเดล 3 ตัว ช่องโมเดลมีรายชื่อจาก OpenRouter และบอกราคากับขนาด context
   - **ตัวสรุป:** สรุปเทิร์นเก่าเป็นราย ID
   - **ตัววิ่งหาข้อมูล:** อ่านสรุปทุก ID แล้วเลือก ควรเป็นโมเดลราคาถูก
   - **ตัวทำงานหลัก:** คุยกับผู้ใช้ **ต้องรองรับ tool calling** ถ้าไม่รองรับ หน้าตั้งค่าจะเตือน
3. สร้างแชตใหม่แล้วเริ่มคุย

ตัวเลือกอื่น: `--port 9000`, `--db path/to/other.db`, `--no-browser`

## สิ่งที่ระบบทำในแต่ละข้อความ

1. ปิดรายการในชั้น 4 ที่หมดอายุ
2. ถ้าติ๊ก "บังคับสแกน" หรือข้อความมีคำที่อ้างถึงเรื่องเก่า เช่น "ที่เคย" "ก่อนหน้า" "ที่ตกลง" ระบบจะสแกนก่อนตอบ (ข้อเสนอ 13.1)
3. ส่ง prompt ให้ตัวทำงานหลัก ประกอบด้วยกฎของระบบ ชั้น 1 และข้อความล่าสุดที่มี `<memory_state>` (ชั้น 4) ต่อท้าย
4. ตัวทำงานหลักเรียก tool ได้:
   - `search_memory`: สแกนสรุปทุก ID ชุดละ `shard_size` ID รันพร้อมกัน ทุกชุดรายงาน `found`, `not_found` หรือ `failed` และชุดที่ล้มเหลวจะลองใหม่ 1 ครั้ง
   - `read_full`: อ่านข้อความเต็ม (ชั้น 3) แทนสรุปของ ID นั้นในชั้น 4
   - `record_decision`: บันทึกข้อตัดสินใจที่ผู้ใช้ตกลง และแทนข้อเก่าได้
   - `add_note`: ต้องอ้าง ID ที่ยังอยู่ในชั้น 1 ถ้าอ้าง ID อื่น โค้ดจะปฏิเสธ
   - `retire_state`: เอาโน้ตหรือข้อมูลที่ดึงมาออก แต่**เอา condition หรือ decision ออกไม่ได้**
5. หลังตอบ ถ้าชั้น 1 มีเทิร์นถึง `compress_at` (ค่าเริ่มต้น 25) จะสรุปรอบละ `round_size` ID อยู่เบื้องหลัง
   ตั้งค่าเริ่มบีบอัดกับขนาดรอบนี้ได้ทั้งแบบรวมในหน้าตั้งค่า และแบบแยกต่อแชตจากแถบบนของแชตนั้น (ไม่ตั้งไว้ = ใช้ค่ารวม)

## กฎที่บังคับด้วยโค้ด ไม่ได้พึ่งแค่ prompt

- `condition` เพิ่มได้จากหน้าเว็บเท่านั้น ถ้าปักจากข้อความ ID ใด ข้อความต้องเป็นส่วนหนึ่งของคำผู้ใช้ตรงตัว
- `note` ต้องอ้าง ID ในชั้น 1
- โมเดลเอา `condition` ออกไม่ได้
- สรุปต้องได้ครบทุก ID ในรอบ ถ้าไม่ครบจะลองใหม่ 1 ครั้ง แล้วแจ้งข้อผิดพลาด โดยเทิร์นยังอยู่ในชั้น 1
- ตัวคัดกรองเลือกได้เฉพาะ ID ที่อยู่ในชุดของตัวเอง และสแกนเฉพาะ ID ที่สรุปแล้ว ไม่สแกน ID ที่ยังอยู่ในชั้น 1
- เพดานงบต่อข้อความ (`max_usd_per_message`) และจำนวนรอบ tool สูงสุด

## หน้าเว็บ

- **แชต:** แต่ละข้อความแสดง ID และบอกว่ายังอยู่ในชั้น 1 หรือสรุปแล้ว ปุ่ม 📌 ใช้ปักคำของคุณเป็นเงื่อนไข
- **แถบบน:** จำนวนในชั้น 1 และชั้น 2 ขนาดชั้น 4 เทียบเพดาน และค่าใช้จ่ายรวม ปุ่ม "สรุปรอบถัดไป" สรุปทันทีโดยไม่รอครบเกณฑ์
- **แท็บชั้น 4:** ดู แก้ และเอารายการออก และเพิ่ม condition หรือ decision เอง
- **แท็บชั้น 2:** ดูและแก้สรุปราย ID
- **แท็บตรวจสอบ:** แยกตามข้อความ บอกขนาด prompt ผลสแกนทุกชุด tool ที่เรียก โทเคน และค่าใช้จ่ายของแต่ละการเรียก
- **แท็บทดสอบสแกน:** ลองถามตัววิ่งหาข้อมูลโดยไม่เปลี่ยนชั้น 4

## ความปลอดภัย

- เซิร์ฟเวอร์รับเฉพาะ `127.0.0.1` และปฏิเสธ Host ที่ไม่ใช่ localhost เพื่อกัน DNS rebinding
- คำขอที่เขียนข้อมูลต้องเป็น `application/json` เว็บอื่นจึงสั่งผ่านเบราว์เซอร์ของคุณไม่ได้
- API key เก็บใน `data/memory.db` แบบไม่เข้ารหัส และ API ไม่ส่ง key กลับมาให้หน้าเว็บ อย่าแชร์ไฟล์ db
